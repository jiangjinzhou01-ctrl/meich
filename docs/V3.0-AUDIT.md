# MGC Digital V3.0 — baseline and implementation decisions

Baseline: latest `main` at `adef44557f44d26699a8ca0bf4fae537fa9271e8`, read on 2026-11-01. Work branch: `feature/mgc-v3-experience`. No repository replacement, new framework or production dependency.

Read README, DESIGN, FUNCTIONS, ROUTES, ASSETS, V2.5-AUDIT, V2.5-DELIVERY, MOTION-SYSTEM; inspected the shared home, hero, journey, culture, card, responsive-image, contact, navigation, case, services, content and deployment sources. Existing baseline contains early selected work, three reading lenses, bilingual routes, original archives, search, honest local-only contact preparation, motion observers and both deployment targets; these were retained.

| Finding | Implementation |
| --- | --- |
| Large home heading covers the photographed exhibition; broad dark overlay loses the material and light of the space. | Give photography and typography separate compositional areas. Preserve actual Gaomiao photography with a local caption gradient only; desktop editorial grid, tablet sizing and independent mobile source crop. CTA has no entrance delay. |
| Gaomiao portrait source was selected implicitly for every `100vw` image, including contexts without that intended composition. | Make mobile art direction explicit with `mobileSource`; ordinary case, next-project and study images continue using their own responsive sizes. |
| Three home projects share essentially the same overlay language. | Gaomiao is the first spatial panorama; Liye uses a light interpretation plate; Potala retains a dark architectural image. Shared card semantics, published responsibilities and routes stay intact. |
| Gaomiao has little visible media after its hero; Liye interpretation image lacks direct detail inspection; Potala material has a low resolution ceiling. | Add one shared ProjectStudy with three case-specific data sets and compositions. Crop Gaomiao photography, compare existing Liye interpretation, switch actual Potala plates. A native image inspector exposes original pixels without invented enhancement. Preserve full archives. |
| Case links lack live chapter state and compact mobile reading controls. | Sticky, horizontally scrollable chapter rail, actual scroll-derived current chapter, count, previous/next links. Anchor offset accounts for the global and chapter navigation. Existing all-work and next-project paths remain. |
| Culture controls are below a long mobile reading panel, and the standalone page repeats a large headline. | Put stage controls before the material and keep them available while reading. Replace the duplicate heading with concise guidance. Add image inspection, selected stage labels and source-to-explanation notes for later stages; preserve the four stages and three lenses. |
| Case-to-service-to-contact paths are indirect. | Add published role rows on services, correct related-project mapping, related capability links and an editable project-context brief. No new capability, client, award, date or outcome claim. |
| Media navigation allows background text through. | Use an opaque ink navigation surface and explicit stacking above chapter controls. |

No live AI, fabricated scan, new transcription, automatic video, scroll hijacking or second animation framework was introduced. Existing CSS motion, MotionProvider, RevealText and ArtifactJourney remain the foundation. No source archive or legacy route was removed.

The first production export caught five English link occurrences pointing to shorthand slugs that do not exist in the source archive. Fixed them through `languagePair` and repeated the export check: 570 HTML pages, zero broken internal links/images. English Liye and Potala keep their existing brochure routes.

The actual mobile Lighthouse pass found LCP 3.3s and high layout work. Inspection identified alternating geometry reads and class/style writes in MotionProvider registration. V3 batches those reads and caches group rectangles before writing. This is a shared-system performance fix, not a second motion implementation. Initial lab evidence is retained as `v3.0-performance-initial.json`; final values and environment are in the QA record.
